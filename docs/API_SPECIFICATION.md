# OtabuPro ERP — API Specification

Status: **Baseline v1.0**. The machine-readable contract is generated by drf-spectacular at `GET /api/v1/schema/` (Swagger UI at `/api/v1/docs/`, ReDoc at `/api/v1/redoc/`). This document defines the conventions every endpoint follows and the endpoint catalogue per module. Endpoints marked **[P1]** exist in Phase 1.

## 1. General conventions
| Topic | Convention |
|---|---|
| Base path | `/api/v1/` — breaking changes go to `/api/v2/`, additive changes don't |
| Format | JSON, UTF-8, `snake_case` fields, ISO-8601 timestamps in UTC (`2026-10-31T09:12:00Z`), dates as `YYYY-MM-DD` |
| Decimals | Money, quantities and rates are serialized as **strings** (`"1250.5000"`) to avoid float loss |
| IDs | UUID strings |
| Company context | Header `X-Company-ID` selects the active company; it must be within the user's scopes (otherwise 403). Defaults to the user's default company |
| Resource naming | Plural nouns, kebab-case: `/inventory/stock-transfers/` |
| State transitions | `POST /{resource}/{id}/{action}/` — e.g. `/procurement/purchase-orders/{id}/submit/`, `/approve/`, `/reject/`, `/post/`, `/cancel/` |
| Request tracing | `X-Request-ID` echoed in every response and error |

## 2. Authentication
- Web: `erp_session` HttpOnly cookie + `X-CSRF-Token` header (matching `erp_csrf` cookie) for unsafe methods.
- Mobile/API clients: `Authorization: Bearer <session token>`.
- 401 `not_authenticated` when no/expired session; 403 `mfa_required` when step-up is needed.

## 3. Errors
Content type `application/problem+json`-compatible:
```json
{
  "type": "validation_error",
  "title": "Invalid input.",
  "status": 400,
  "detail": "One or more fields failed validation.",
  "errors": [{"field": "lines[2].quantity", "code": "min_value", "message": "Ensure this value is greater than 0."}],
  "request_id": "01JBX…"
}
```
| Status | `type` codes |
|---|---|
| 400 | `validation_error`, `parse_error` |
| 401 | `not_authenticated`, `authentication_failed`, `session_expired` |
| 403 | `permission_denied`, `mfa_required`, `account_locked` |
| 404 | `not_found` (also returned for records outside the caller's scope), `feature_disabled` |
| 409 | `version_conflict`, `invalid_state_transition`, `idempotency_in_progress` |
| 422 | `business_rule_violation` (e.g. `insufficient_stock`, `period_closed`, `credit_limit_exceeded`), `idempotency_key_reused` |
| 429 | `throttled` |
| 500 | `server_error` (no internals leaked) |

Business rule violations carry a stable `code`, for example `{"type":"business_rule_violation","code":"insufficient_stock","detail":"…","meta":{"item_id":"…","available":"3.000000"}}`.

## 4. Pagination, filtering, sorting
- **Page-number pagination** for documents and master data: `?page=2&page_size=50` (max 200). Response: `{"count", "next", "previous", "results"}`.
- **Cursor pagination** for ledgers, audit and activity streams: `?cursor=…&page_size=100`. Response: `{"next", "previous", "results"}`.
- Filtering: field filters `?status=approved&warehouse_id=…`, ranges `?posting_date_after=2026-04-01&posting_date_before=2026-06-30`, `?search=` full-text on configured fields.
- Sorting: `?ordering=-created_at,code` restricted to an allow-list per endpoint.
- Sparse fields (optional): `?fields=id,number,status`.

## 5. Concurrency and idempotency
- Mutable documents return `version`; `PATCH`/`PUT` and transition actions require `version` in the body (or an `If-Match` header). Mismatch → 409 `version_conflict`.
- `Idempotency-Key: <uuid>` is **required** on all posting and transition endpoints and all mobile writes, optional elsewhere. Same key + same payload → stored response replayed with header `Idempotent-Replayed: true`; same key + different payload → 422 `idempotency_key_reused`; in-flight duplicate → 409 `idempotency_in_progress`.

## 6. Endpoint catalogue

### 6.1 Platform [P1]
| Method & path | Description | Permission |
|---|---|---|
| `GET /health/live`, `GET /health/ready` | Liveness / readiness (DB, Redis) | public (internal) |
| `GET /api/v1/schema/`, `/docs/`, `/redoc/` | OpenAPI | authenticated in production (configurable) |
| `GET /api/v1/meta/feature-flags/` | Effective flags for caller | authenticated |

### 6.2 Auth and identity [P1]
| Method & path | Description |
|---|---|
| `POST /api/v1/auth/login/` | `{email, password, client_type}` → `200 {status:"authenticated", session…}` or `200 {status:"mfa_required", challenge_token}` |
| `POST /api/v1/auth/login/mfa/` | `{challenge_token, code}` (TOTP or recovery code) → session |
| `POST /api/v1/auth/logout/` | Revoke current session |
| `GET /api/v1/auth/me/` | Profile, active company, companies available, effective permissions (codes + scopes), feature flags, MFA status |
| `POST /api/v1/auth/step-up/` | `{code}` re-verify MFA for the current session |
| `POST /api/v1/auth/password/change/` | Change password (revokes other sessions) |
| `GET /api/v1/auth/sessions/` · `DELETE /api/v1/auth/sessions/{id}/` | List and revoke own sessions |
| `POST /api/v1/auth/mfa/totp/setup/` | Start enrolment → `{secret, otpauth_uri}` |
| `POST /api/v1/auth/mfa/totp/confirm/` | Confirm with a code → recovery codes (shown once) |
| `POST /api/v1/auth/mfa/recovery-codes/regenerate/` | Requires step-up |
| `GET/POST /api/v1/identity/users/` · `GET/PATCH /api/v1/identity/users/{id}/` | User admin (`identity.user.*`) |
| `POST /api/v1/identity/users/{id}/deactivate/` · `/unlock/` · `/reset-mfa/` · `/revoke-sessions/` | Admin actions (`identity.user.manage`) |

### 6.3 Organization [P1]
`/api/v1/organization/companies/`, `/branches/`, `/departments/`, `/facilities/`, `/warehouses/`, `/fiscal-years/`, `/fiscal-years/{id}/periods/` — CRUD (deactivate instead of delete when referenced), scoped by the caller's assignments. `GET /api/v1/organization/scope-tree/` returns the scope tree visible to the caller.

### 6.4 Authorization [P1]
| Path | Description |
|---|---|
| `GET /api/v1/authorization/permissions/` | Permission catalogue (read-only, seeded from code registry) |
| `/api/v1/authorization/roles/` (+ `/{id}/permissions/`) | Roles and their permissions; templates read-only, `clone` action |
| `/api/v1/authorization/role-assignments/` | Grant and revoke scoped roles (`authorization.role_assignment.assign`); SoD check on create |
| `/api/v1/authorization/policies/` | ABAC policies (`authorization.policy.manage`, requires MFA) with `POST /validate/` dry-run |
| `/api/v1/authorization/sod-rules/` | SoD rules; `GET /sod-conflicts/` report |
| `/api/v1/authorization/approval-limits/` | Approval limits |
| `POST /api/v1/authorization/check/` | Explain a decision for a given user/action/resource (admin diagnostic, `authorization.policy.manage`) |

### 6.5 Audit [P1]
`GET /api/v1/audit/events/` (cursor; filters: actor, action, resource_type, resource_id, outcome, date range) — `audit.audit_event.read`. `GET /api/v1/audit/events/verify-chain/` — `audit.audit_event.manage`. No write endpoints.

### 6.6 Approvals and notifications [P1b]
| Method & path | Description |
|---|---|
| `GET /api/v1/approvals/inbox/` · `GET /api/v1/approvals/inbox/count/` | Requests whose current step the caller may decide (directly or as delegate) |
| `GET /api/v1/approvals/requests/?mine=true&status=` · `GET /api/v1/approvals/requests/{id}/` | Requests visible to the caller: own, decided, awaiting them, or oversight within scope (`approvals.approval_request.read`) |
| `POST /api/v1/approvals/requests/{id}/approve/` · `/reject/` | `{comment, version}`; **`Idempotency-Key` required**; reject requires a comment; step-up MFA when the document permission requires it |
| `POST /api/v1/approvals/requests/{id}/withdraw/` | Requester only |
| `GET/POST /api/v1/approvals/matrices/` · `PATCH /api/v1/approvals/matrices/{id}/` | Approval routes (`approvals.approval_matrix.manage`, MFA); levels replaced atomically, in-flight requests keep their snapshot |
| `GET /api/v1/approvals/document-types/` | Registered routable document types |
| `GET/POST /api/v1/approvals/delegations/` · `POST /api/v1/approvals/delegations/{id}/revoke/` | Own delegations (max 90 days) |
| `GET /api/v1/notifications/?unread=true` (cursor) · `GET /api/v1/notifications/unread-count/` · `POST /api/v1/notifications/mark-read/` | Own notifications |
| `GET/PUT /api/v1/notifications/preferences/` | Per category × channel; approval and security in-app notifications are mandatory |
| `GET /api/v1/identity/directory/?search=` | Colleague lookup for pickers: id, name, email only; ≥ 2 characters; max 20 |
| `GET/PATCH /api/v1/admin/feature-flags/` · `GET /api/v1/admin/outbox-events/` (+ `retry`) | Platform administration |

## 7. WebSocket
`wss://<host>/ws/v1/stream/` authenticated via cookie or `?token=` (mobile only, short-lived ticket from `POST /api/v1/auth/ws-ticket/`). Server → client messages: `{"type":"notification.created","id":…}`, `{"type":"approval.count","value":3}`, `{"type":"document.updated","resource_type":…,"id":…,"version":…}`. Clients refetch over REST.
